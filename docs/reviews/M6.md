# Milestone 6 review: The builder

Tag `v0.6.0` · planned 12 November 2026 · written by Claude Code; reviewed by spec-reviewer, auditor, then Claude in Cowork.

## Plan

### What it builds

The builder a shopper uses: everything under The builder in the spec but the layered picture, which is milestone 7's.

1. **Owed first.** Issue #34's nine escaped mutants and #25's three, looked at again; #28, the default price context's rows filled by the reindex job, so the builder's first request on a shop does not pay 470 ms; #7, where the test shop's front page spends its largest paint before the builder adds to it.
2. **Where it renders.** The Builder block (`block.json` apiVersion 3, `render.php`, `supports.interactivity`, a `kit` attribute, an editor preview that is the server's render), and the kit's own page through `woocommerce_cbuild_kit_add_to_cart`. Both call one renderer.
3. **One template per piece,** with Interactivity API directives, rendered by the server and re-rendered by the private store `creative-skateboard-builder` from the state route's answer. No markup is built in the script.
4. **Without JavaScript:** every step, the change panel and the review are GET forms with the `cbuild[…]` parameters in slot order; Add to cart posts to WooCommerce's own handler. With JavaScript, each step change is a history entry with the same URL.
5. **Ways in:** blank, a preset tile, a build link, and a deck's link with the deck picked ("Start with a width" where there is none). Saved builds arrive in milestone 8.
6. **A step:** the heading and progress list; cards with a native radio each, a distinct name, "+$", "Free" or "Included", stock and a fit label; recommendations, labelled; the hidden-parts disclosure with its reasons; filters, in a drawer on phones; 24 at a time with Show more; sold-out parts last, each linking to its own page.
7. **The change panel,** with "Use these" and "Undo"; a step of its own without JavaScript.
8. **The total and delivery:** the summary beside the steps, the phone bar with "Next: X" whose total opens the parts list; assembly in the total from step one; the delivery line from the two filters milestone 5 added, and worded from WooCommerce's shipping zones where neither answers; `cbuild_summary_notes`.
9. **The picture, for now:** the labelled "What's in the box" layout from the parts' photos, with its written description.
10. **The review:** fit ticks, Change links, assembly with its fee and lead time, the date, the total and the returns notice.
11. **Getting it to the cart:** the Store API's add, then `wc-blocks_added_to_cart` and `cbuild:added`; Copy link; Edit build on the kit's cart line, which reopens the builder and replaces the build.
12. **Accessibility mechanics:** focus to each step's heading, one polite status region in the page from the start, the error summary, the page title.
13. **Motion:** view transitions between steps and a settling card; nothing under reduced motion.
14. **SEO:** a page carrying `cbuild[…]` is `noindex, follow` with a canonical to the clean page; step and Change links carry `rel="nofollow"`; the clean page has its content in the HTML.
15. **Carried from milestone 5:** a first build added without leaving the page has its cart styles (D-132); PayPal Payments' buttons on a kit's page, and a guest's GeoIP lookup measured (D-139).

Not in this milestone: the layered picture, the composed image and the share card's picture (milestone 7); saved builds, emails, the Build box and the ticket (milestone 8).

### The public API it adds

Each goes into `docs/HOOKS.md` with `@since 0.6.0`, the snapshot and the changelog in the commit that adds it.

- **The block** `creative-skateboard-builder/builder`, with the attribute `kit`.
- **The build link:** `cbuild[<slot key>]=<part ID>`, `cbuild[step]`, `cbuild[assembly]` and `cbuild[preset]`, as the spec fixes it. What the no-JavaScript forms need beside them (the picks before a change, a filter, how many options are shown) is decided as each is built and written down then.
- **The state route** gains fields, and removes none: what the picture shows and its description, the delivery line, the summary's notes, each step's filters, and what the template needs that the answer does not hold yet. Its arguments stay the spec's five.
- **Filters:** `cbuild_part_classes` (a card's classes), `cbuild_summary_notes` (lines under the total), and `cbuild_builder_url` (where a kit's builder is: the kit's own page unless a shop answers with the page its block is on, D-008).
- **DOM events:** `cbuild:pick` and `cbuild:added`, on the builder's element, bubbling.
- **The cart:** the parameter that says which build an add replaces, and the Edit build link on the kit's line in all three carts.
- **CSS:** the documented classes and custom properties a theme may set.
- The store is private and locked. Nothing of it is public.

### Decisions I expect to record

- **One renderer, two ways in.** `Front\Builder` (or its like) renders from a `StateAnswer`; the block's `render.php` and the kit page's hook each call it and hold nothing else. The state route's answer and the server's first render come from one service, so they cannot differ.
- **Templates are data-driven, not looped twice.** A list is one `<template data-wp-each>` with the server's rendering of the same items beside it, as the Interactivity API expects, from one template file per piece.
- **No client-side router.** The store fetches the state route and the template re-renders; `history.pushState` carries the URL the form would have made. `@wordpress/interactivity-router` would fetch whole pages, which is the no-JavaScript path's cost on every pick.
- **Strings come from the server:** in the markup and in `wp_interactivity_state()`. The script carries none.
- **The script's size is spent deliberately.** `@wordpress/interactivity` is WordPress's own module and is not in the 15 kB. The store is one module; the cart's add and Copy link load with it only if they fit, and otherwise on first use.
- **Edit build replaces by adding first.** The new build is validated and added, then the old one removed, so a refusal leaves the cart as it was.
- **Visual snapshots run in CI's container only,** on Kadence, Storefront and Twenty Twenty-Five, dark and light, as milestone 1 set up.
- **The delivery line without a filter** is worded from the shop's zones for the address WooCommerce holds, and says nothing where it holds none.
