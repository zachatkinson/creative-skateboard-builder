### The two tables, proposed

Tables change only with Zach after this milestone, so the columns are set out here for him to confirm or change. Both follow the spec's Data model.

```sql
CREATE TABLE {prefix}cbuild_specs (
  part_id bigint(20) unsigned NOT NULL,         -- the product or variation
  spec varchar(32) NOT NULL,                    -- deck_width, axle_width, hole_pattern …
  number decimal(10,4) NULL,                    -- a measured value, in the spec's unit
  text varchar(64) NULL,                        -- a short value (new, old, both; a height class)
  source varchar(16) NOT NULL,                  -- field, attribute or table
  source_ref varchar(191) NOT NULL DEFAULT '',  -- pa_width; or the spec table and size
  indexed_at datetime NOT NULL,                 -- UTC, from the Clock
  PRIMARY KEY  (part_id,spec),
  KEY spec_number (spec,number),
  KEY spec_text (spec,text)
);
CREATE TABLE {prefix}cbuild_builds (
  id bigint(20) unsigned NOT NULL AUTO_INCREMENT,
  uuid char(36) NOT NULL,
  user_id bigint(20) unsigned NOT NULL,
  kit_id bigint(20) unsigned NOT NULL,
  picks longtext NOT NULL,                      -- JSON: slot key to part id
  assembly tinyint(1) NOT NULL DEFAULT 1,
  name varchar(100) NOT NULL DEFAULT '',
  created_at datetime NOT NULL,
  updated_at datetime NOT NULL,
  PRIMARY KEY  (id),
  UNIQUE KEY uuid (uuid),
  KEY user_id (user_id)
);
```

### Review notes from Claude in Cowork, folded in on 9 November 2026

Received after step 2 and before step 3. Each was checked against the installed source first; all six hold.

1. **The migration lock** is one atomic `INSERT IGNORE`, taken over by compare-and-swap, read from the table (D-021). The "two at once" test runs two `wp` processes against one database, so a lock that only looks atomic fails it.
2. **Where migrations run** (D-022): inline only for `manage_woocommerce` on a non-AJAX admin page; everywhere else one unique `cbuild_migrate` is queued on `init`. New test: a front-end request with the version behind runs nothing inline, queues one job, and the page renders.
3. **Below the floors** (D-023): the main file checks PHP and WordPress before the autoloader, with WooCommerce; `Support\Requirements` is unit-tested with injected versions; CI lints the main file, `uninstall.php` and the check on PHP 7.4.
4. **Uninstall with WooCommerce off** (D-024): deactivation unschedules pending actions; uninstall deletes the group's rows through Action Scheduler when loaded, else with prepared SQL on its tables. Tested both ways, the second through `wp plugin uninstall` with WooCommerce deactivated.
5. **Network activation** (D-025) installs every site; a site added later installs itself on its first admin load. Tested.
6. **The spec fix** (D-026): the attribute mapping and the winning source are shop-wide settings; the spec was updated. No table changes.

Also: `Schema::sql()` carries no comments, since `dbDelta()` splits on semicolons; and the SBOM lists the non-dev Composer packages and the npm `dependencies` webpack bundles (D-030).

Steps 3 to 7 of the order of work carry these. The public API table gains nothing: the unique action is the `cbuild_migrate` already listed.
