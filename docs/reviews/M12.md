# Milestone 12: Shop settings and the backlog (1.2.0)

## Plan

The roadmap has no milestone 12. Its scope is Zach's, from 24 November 2026: every open issue that can be fixed, and Cowork's findings from its review of 1.1.0, which join when the review arrives. That night's review of the product added four settings a shop could only reach through a filter, and two repository fixes.

### What it builds

- **Settings a shop reaches from wp-admin** (CLAUDE.md: anything a shop needs must also work from wp-admin, since the demo's host has no SSH or WP-CLI). Each one's filter stays and answers last, so a plugin like Skatehouse Core keeps working.
  - **#113, the builder page.** A kit's Build tab chooses the published page its Builder block is on. The kit's page, a deck's "Make it a complete" and the cart's Edit build go there. Today only `cbuild_builder_url` can send them.
  - **#114, the width guide.** The kit's rows under "Not sure of your width?", edited or hidden. Today the plugin's US shoe sizes, or `cbuild_width_guide`.
  - **#115, the start button.** Whether "Build a complete with this deck" shows on the kit's parts' pages. Today only `cbuild_start_button` can turn it off.
  - **#116, a part kept out.** A product's or variation's **Not offered in the builder**, as `cbuild_part_available` returning false does now.
- **The repository:**
  - #111: markdownlint-cli2 in `npm run check`, /verify, CI and the pre-commit hook, approved by Zach as the 2026 standard;
  - #112: a `.gitattributes` (line endings, binaries, export-ignore, linguist), and the `.gitignore` and `.distignore` tidy;
  - the WooCommerce pin moved to its newest release (D-145).
- **The open flakes:**
  - #108: the keyboard-only build's cart read empty after Add to cart;
  - #93: Firefox never set the ready mark;
  - #110: the review shot's link a pixel lower, quarantined in 1.1.0;
  - #75: Lighthouse's thin headroom.
- **Cowork's findings on 1.1.0**, folded in as they arrive (D-223).
- **#95, the canary**, stays open: it is a standing tracker, red only when WordPress trunk or WooCommerce's pre-release is.

### Spec sections it touches

- The kit's Build tab, and What Skatehouse needs (#113, #115).
- The deck step's width question (#114).
- Parts and slots, and the Catalogue check (#116).
- Where the builder renders, and the cart's Edit build (#113).

### The public API it adds

Each goes in `docs/HOOKS.md` with `@since 1.2.0`, `docs/SETTINGS.md`, and the API snapshot:

- In a new kit document, `_cbuild_settings` (`schema/kit-settings.json`), three keys. The plan first put them in `_cbuild_layout`; 1.1.0's schema for that refuses a key it does not know, so a rollback would have left every kit saved on 1.2.0 unreadable (the audit's blocker, D-354):
  - `builder_page`: a page's ID, or none;
  - `width_guide`: rows, or hidden;
  - `start_button`: a bool.

  A kit saved before 1.2.0 has none of them and behaves as now.
- A product and variation meta key for "Not offered in the builder", read through the same path as `cbuild_part_available`.

No route, table or event is added or changed, and nothing public is renamed or removed.

### Risks, by dimension

| Dimension | What could go wrong | What catches it |
| --- | --- | --- |
| DRY and SOLID | A setting read in four places, or a second path beside the filter's | One reader per setting, used where the filter was; the setting feeds the filter's first value; `composer arch` |
| Anti-patterns | Logic in a hook; a setting's admin markup built in PHP strings | Hooks call services; one template per panel section; review |
| Security | The builder page chosen as any URL, a draft page, or another site's; the width guide's rows stored as HTML; a capability missed on save | Only a published page holding the kit's block, re-checked on use; rows sanitised as text; `manage_woocommerce` and the nonce WooCommerce's product save carries; integration tests for each |
| Privacy | None: shop settings, no shopper data. PRIVACY.md lists the new keys | `docs/PRIVACY.md` |
| Accessibility | The Build tab's new fields unlabelled; the width guide's editor reachable by mouse only; the guide hidden but still announced | Labels and descriptions per field, an editor of plain inputs and buttons, axe on the admin screens, `hidden` removing it from the page |
| Internationalisation | The shop's own width rows passed through the plugin's translations; strings concatenated | Owner content passes through `cbuild_kit_text`, as other kit texts do; `_n()` and `i18n:check` |
| SEO | A builder page on another page left with two canonical pages for one kit | The kit's page keeps sending a visitor to the builder page, as `cbuild_builder_url` does now; the build-link robots rules (#88) still hold |

| Upgrades and compatibility | A 1.1.0 container can't build a changed class; a kit saved before 1.2.0 behaves differently | D-208's with-ers for any changed constructor; `npm run upgrade:all`; tests for a kit with no new keys |
| Resilience | A chosen page deleted later; a part kept out while in a saved build or the cart | A missing page falls back to the kit's page; a part kept out is refused as `part_not_in_slot` on the next check, as the filter's answer is now |
| UX and content | Settings worded as code, or placed away from where a shop looks | Each field in the Build tab or the Part specs panel beside what it changes, in plain words, with what it does when empty |
