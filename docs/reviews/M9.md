### For Zach

Should-fixes I did not fix, which need your answer before the tag, since only you can defer one:

1. **O21, Redis.** With a persistent object cache, the state route's first request after a part changes is 85.6 ms p95, over the 80 ms budget. Without one it is 66.2 ms. The warm requests are faster with Redis (45.2 ms). Each cache miss is a round trip, and I tried batching the two loops of the plugin's own reads. Measured beside a running update test, it showed no gain I could trust, so it is not in this branch. Batching misses where WooCommerce reads its products is the next place to look. Do you want this fixed before the tag, or the budget written for a site without a persistent cache, as the cold test already says it models?
2. **O19, the grip's sizes.** The spec says grip sheets and strips have a Sheet size such as "9 × 33 in", and the grip slot picks by it. The attribute mapping reads one number, so a "9 × 33" term feeds neither width nor length. The import and the Part specs fields do work. Should a mapping line read one side of such a value, or do grip sizes come from the specs import?
