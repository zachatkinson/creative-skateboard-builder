**#139, the 3D view**, to Cowork's spec:

- **Settings,** two Build tab switches in `_cbuild_settings` (`feature-switches-per-kit`):
  - "3D view", off by default, so the update changes nothing;
  - "Trick buttons", on by default and shown only with 3D on.
- **Loading.** A "View in 3D" button loads the 3D chunk only when pressed. The view then stays live on every step. Before the press, the page's bytes, LCP and CLS match 3D off.
- **The scene's sizes come from the domain.** A new `Domain\Scene` takes a build's picks and specs and gives every part's size and place in millimetres, with the usual values it assumed, as `Layout` does for the 2D board. The browser draws what the server measured and decides nothing.
  - **Deck:** its outline from width, length, wheelbase, nose and tail; concave and kick from the deck's specs or a usual value; the plies drawn on its edge.
  - **Trucks:** by axle width and height, on the deck's real hole pattern (new or old school), with the casting simplified.
  - **Wheels:** by diameter and width, with a contact band and a bearing seat.
  - **Bolts** at the 8 holes, and risers by thickness.
  - **The copy says so:** sizes true to scale, shapes simplified.
- **New specs,** where a part's specs don't yet carry a size the scene needs:
  - a deck's nose and tail lengths, concave depth and kick angle;
  - a wheel's width.

  Each is optional, through the import and Part specs. A deck or wheel without one gets a usual value, and the Catalogue check lists it.
- **Textures** are the layer renditions the 2D board already caches: 1 px/mm on a phone, 2 px/mm on a desktop. Each goes through `cbuild_composed_layer` with a new use, `3d`, so Mature Content can blur a flagged deck's graphic on the board (`feature-switches-per-kit`, Cowork's standing rule).
- **Lighting:** RoomEnvironment through PMREM, built after the first frame shows, with no HDR file.
- **Rendering:**
  - frames are drawn only on demand, while something moves;
  - drawing pauses off-screen and in a hidden tab;
  - the pixel ratio is capped at 2, or 1.5 on a low-memory device;
  - everything is disposed on close;
  - a part change swaps that part's meshes only.
- **Camera and controls:**
  - the camera turns to each step's side;
  - drag to orbit, pinch or scroll to zoom, the arrow keys and + and − for the same;
  - reset, top, underside and the graphic close-up, all as real buttons.
- **Tricks:** ollie, kickflip, heelflip, pop shove-it and 360 flip, timed from the teardown (an ollie about 0.9 s, a 360 flip about 1.5 s).
- **Accessibility:**
  - the canvas carries the build sentence the 2D board has;
  - reduced motion turns off spin and tricks;
  - on a phone, a vertical swipe still scrolls the page.
- **Fallback:** no WebGL2, a lost context or any error returns to the 2D board with a short message, and never blocks Add to cart.

### The public API it adds

Each goes in `docs/HOOKS.md` with `@since 1.4.0`, in `docs/SETTINGS.md` where it is a setting, and in the API snapshot:

- **In `_cbuild_settings`** (D-354): `view_3d` and `tricks` (on). A kit saved before 1.4.0 has neither, and reads as 3D off and tricks on. A new kit's Build tab ticks the 3D view, so it is on from its first save (Zach, 26 Nov: "On for new kits"; D-476).
- **Specs** (`SpecKey`, the import's columns and Part specs): `nose_length`, `tail_length`, `concave_depth`, `kick_angle` and `wheel_width`. These are additions; nothing is renamed.
- **`cbuild_composed_layer`:** a new `$use` value, `3d`.
- **A filter, `cbuild_scene`:** the scene's sizes for a build, answering after the domain.
- **The state route's answer:** a `scene` object when the kit's 3D is on (`schema/state.json`). It is an addition, so no key is renamed.
- **Builder classes:** `cbuild-3d` and its canvas `cbuild-3d__canvas`, which carry the deck's `cbuild_part_classes`.

No table is added, and nothing public is renamed or removed.

### Decisions I expect to record

From D-462. Each is decided on researched practice, recorded, and listed for Zach:

### Risks, by dimension

| Dimension | What could go wrong | What catches it |
| --- | --- | --- |
| DRY and SOLID | A second geometry in the browser that drifts from `Layout`'s 2D sizes; the scene rebuilt per part | One `Domain\Scene` sharing `Layout`'s usual values; the renderer interface the SPEC names; a part change swaps one group, and a browser test counts the scene's objects before and after; `composer arch` |
| Anti-patterns | Fit or sizes decided in the 3D chunk; markup built in JavaScript for its buttons | The scene is server data; the controls are a server template the store shows; review |
| Security | A texture URL or size from the link trusted; a part's artwork loaded from another origin | Sizes come only from the server's scene; textures are the plugin's own rendition URLs, same origin, and an integration test feeds the scene a hostile spec |
| Privacy | None new: the scene holds part sizes and the shop's own images, and nothing about the shopper | PRIVACY.md is unchanged, and says so in the review |
| Accessibility | A canvas no screen reader can read; controls only by drag; a trick or spin under reduced motion; a swipe trapped on a phone | The canvas named with the build sentence; every control a button reachable by keyboard with a visible focus; a reduced-motion test that counts no animation frames; a phone test that scrolls past the canvas; axe on every state |
| Internationalisation | Button and fallback text left in English; "sizes true to scale" concatenated; sizes in the wrong unit | Every string through the text domain, from server templates; the fr-ca and rtl projects; units through the translatable patterns |
| SEO | The 3D chunk or canvas pushes LCP or CLS on a page with 3D on | On-against-off Lighthouse runs and the layout-shift test before the press |
| Performance | three in the builder's 15 kB script; frames drawn while idle; a GPU leak on close; a part change rebuilding everything | The 3D chunk's own 200 kB budget line in `npm run budget` and CI; a count of zero frames over 5 s idle, off-screen and hidden; a dispose test that counts the renderer's geometries and textures back to zero; the swap-one-part test |
| Testing | Geometry tested only at one width; canvas pictures flaky across GPUs; tricks untested | Unit tests at every shape and pattern's extremes, holes meet holes for both patterns, a 0.5 mm accuracy limit; the visual project's fixed angles with a stated tolerance; a trick test that checks its end pose and duration; Infection on changed lines |
| Upgrades and compatibility | A 1.3.0 kit without the new switches turns 3D on; a 1.3.0 deck without the new specs breaks the scene; a browser without WebGL2 | Both switches default as stated, tested on a kit with no new keys; usual values for every missing spec; `npm run upgrade:all`; the no-WebGL test |
| Resilience | A lost context or a shader error that leaves a blank box or blocks Add to cart; a texture that fails to load | A forced `WEBGL_lose_context` test and an injected error test that both return to the 2D board with the message and add to cart; a texture failure falls back to the deck's colour |
| UX and content | 3D that reads as a promise of exact shapes; controls that crowd the phone's bar; tricks that feel like a toy in the way | The copy says sizes are true and shapes simplified; #153 first, and phone walkthroughs; tricks behind their own switch and never playing on their own |
